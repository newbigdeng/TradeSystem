# 00 组播接口：订单正常，行情收不到

修复日期：2026-09-30；文档核对：2026-10-04。修改：`ff20fd7 → e2ea493`。

问题已经修复：发送端和接收端都使用配置中的 `lo`，增量行情及晚加入客户端的快照恢复均跑通。

## 测试发现了什么

交易所和客户端能通过 TCP 收发订单，但客户端没有收到 UDP 组播行情。旧测试运行 65 秒，网关出现 911 条 ACCEPTED 和 1,166 条 FILLED 日志，行情接收日志为 0。这些是日志行数，不是成交手数。

环境为 Ubuntu 26.04.1 LTS、GCC 15.2.0、CMake 4.2.3。同机运行，UFW 开启；增量组为 `233.252.14.3:20001`，快照组为 `233.252.14.1:20000`，配置接口均为 `lo`。

## 问题在哪里

配置写了 `lo`，Socket 却没有真正指定组播接口：

- 发送端缺少 `IP_MULTICAST_IF`，内核按路由选择 `ens33`。
- 接收端用 `INADDR_ANY` 入组，同样让系统选择接口。
- `McastSocket` 没保存接口名，入组时也没传下去。

路由查询显示组播目标走 `ens33`，内核日志出现对应 UFW 拦截。独立探针不指定接口、指定 `ens33` 都超时，指定 `127.0.0.1` 则能收到原消息。

关键区别是：**组播地址说明加入哪个组，接口地址说明从哪张网卡收发。两者不能互相替代。**

## 怎样修复

发送端在连接组播目标前设置 `IP_MULTICAST_IF`；接收端把配置接口的 IPv4 地址写入 `ip_mreq.imr_interface`。封装保存 `iface_` 并传给入组函数。

原调用：

```cpp
return Common::join(socket_fd_, ip);
```

修复后：

```cpp
return Common::join(socket_fd_, ip, iface_);
```

无效接口和非组播地址明确失败，避免错误配置退回默认接口。完整发送条件、入组校验及封装改动见[源码对照](00_source_changes.md)。
